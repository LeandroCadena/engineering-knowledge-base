# AWS Lambda

## Definition

AWS Lambda is a **serverless compute service** that allows developers to run code without provisioning or managing servers.

Instead of deploying applications to virtual machines or containers, developers upload individual functions that execute only when they are triggered.

Lambda automatically provides the infrastructure required to execute those functions, including provisioning compute resources, scaling the execution environment, and handling availability.

Its primary responsibility is executing application code in response to events.

Lambda is **not** responsible for storing data, exposing public APIs, authenticating users, or orchestrating distributed systems. Instead, it integrates with other AWS services that provide those capabilities.

---

## How it Works

A Lambda function is executed whenever an event occurs.

An **event** is any action that triggers the execution of a function.

When an event is received, AWS creates an execution environment if necessary, runs the function, returns the result, and keeps the environment available for future requests when possible.

![How it works](/docs/aws-lambda/how-it-works.png)

Because compute resources exist only while the function is executing, applications automatically scale according to demand without requiring developers to manage servers.

---

## How it Fits into the Ecosystem

Lambda is the compute layer of many AWS architectures.

Rather than exposing APIs, storing data, or managing authentication, Lambda focuses exclusively on executing business logic.

Other AWS services trigger Lambda whenever work needs to be performed.

![How it fits](/docs/aws-lambda/how-it-fits.png)

This event-driven model allows applications to react automatically to events generated by other AWS services.

---

## What It Looks Like

AWS Lambda is managed through the **AWS Management Console**.

This is where developers create functions, edit code, configure execution settings, connect event sources, monitor performance, and test their applications.

The interface is organized around a few core areas:

- **Function Overview** – Displays the event sources that trigger the function and the AWS services it interacts with.
- **Code Editor** – Allows developers to write, edit, or upload the function code.
- **Configuration** – Contains runtime settings such as memory allocation, timeout, environment variables, IAM permissions, networking, and concurrency.
- **Monitoring** – Shows metrics, logs, and execution data collected through Amazon CloudWatch.

![AWS Lambda Console](/docs/aws-lambda/how-it-looks.png)

Most day-to-day Lambda development happens from this interface. Developers typically create functions, configure triggers, deploy new versions, test executions, review logs, and adjust runtime settings without managing any underlying infrastructure.

## Common Use Cases

AWS Lambda is commonly used to execute short-lived, event-driven workloads without managing servers.

Some of the most common use cases include:

### REST APIs

![REST API Flow](/docs/aws-lambda/use-case-rest-api.png)

A client sends an HTTP request to API Gateway, which invokes a Lambda function. The function executes the business logic, interacts with other services if necessary, and returns a response.

---

### File Processing

![File Processing Flow](/docs/aws-lambda/use-case-file-processing.png)

When a file is uploaded to Amazon S3, the upload event automatically triggers a Lambda function. The function can resize images, extract metadata, convert formats, or perform other processing tasks before storing the result.

---

### Queue Processing

![Queue Processing Flow](/docs/aws-lambda/use-case-queue-processing.png)

Applications place messages into Amazon SQS, and Lambda automatically processes each message as it becomes available. This pattern is commonly used for asynchronous background work.

---

### Scheduled Tasks

![Scheduled Execution Flow](/docs/aws-lambda/use-case-scheduled.png)

Amazon EventBridge can invoke Lambda functions on a schedule, allowing applications to generate reports, clean up resources, synchronize data, or execute recurring maintenance tasks.

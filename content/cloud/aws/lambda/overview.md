# AWS Lambda

## Definition

AWS Lambda is a **serverless compute service** that allows developers to run code without provisioning or managing servers.

Instead of deploying applications to virtual machines or containers, developers upload individual functions that execute only when they are triggered.

Lambda automatically provides the infrastructure required to execute those functions, including provisioning compute resources, scaling the execution environment, and handling availability.

Its primary responsibility is executing application code in response to events.

Lambda is **not** responsible for storing data, exposing public APIs, authenticating users, or orchestrating distributed systems. Instead, it integrates with other AWS services that provide those capabilities.

---

## How it Works

A Lambda function is executed whenever an event occurs.

An **event** is any action that triggers the execution of a function.

For example:

- An HTTP request received through API Gateway.
- A file uploaded to Amazon S3.
- A message arriving in Amazon SQS.
- A scheduled event created with Amazon EventBridge.

```text
Event

↓

AWS Lambda

↓

Function Execution

↓

Result
```

When an event is received, AWS creates an execution environment if necessary, runs the function, returns the result, and keeps the environment available for future requests when possible.

Because compute resources exist only while the function is executing, applications automatically scale according to demand without requiring developers to manage servers.

---

## How it Fits into the Ecosystem

Lambda is the compute layer of many AWS architectures.

Rather than exposing APIs, storing data, or managing authentication, Lambda focuses exclusively on executing business logic.

Other AWS services trigger Lambda whenever work needs to be performed.

For example:

```text
Client
    │
    ▼
API Gateway
    │
    ▼
AWS Lambda
    │
    ▼
DynamoDB
```

In other scenarios:

```text
Amazon S3

↓

AWS Lambda

↓

Image Processing
```

```text
Amazon SQS

↓

AWS Lambda

↓

Background Processing
```

This event-driven model allows applications to react automatically to events generated by other AWS services.

---

## Real-World Usage

Lambda is commonly used when applications need to execute relatively small, independent pieces of logic without managing servers.

Typical use cases include:

- REST API backends.
- Processing uploaded files.
- Image resizing.
- Sending emails or notifications.
- Background job processing.
- Event-driven workflows.
- Scheduled tasks.
- Data transformations.
- Integration between AWS services.

Lambda is especially popular in serverless architectures because compute resources are created only when needed and automatically scale with incoming demand.

## Practical Examples

### REST API

```text
Client

↓

API Gateway

↓

Lambda

↓

Database
```

A client sends an HTTP request.

API Gateway forwards the request to Lambda.

Lambda executes the business logic and retrieves or stores data.

---

### File Processing

```text
User

↓

Amazon S3

↓

Lambda

↓

Generate Thumbnail
```

A user uploads an image.

The upload event automatically triggers a Lambda function that creates a thumbnail.

---

### Queue Processing

```text
Application

↓

Amazon SQS

↓

Lambda

↓

Process Order
```

An application places a message in a queue.

Lambda automatically processes each message as it becomes available.

---

### Scheduled Execution

```text
Amazon EventBridge

↓

Lambda

↓

Daily Report
```

A scheduled event executes a Lambda function every day to generate reports or perform maintenance tasks.
